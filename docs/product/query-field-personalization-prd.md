# 查询项个性化配置 PRD

## 1. 背景与目标

出口订单包含 18 个查询项。原方案按查询项数量和视口宽度决定页面直出项，导致字段在页面与高级筛选抽屉之间自动跳位，也无法满足不同岗位对高频条件的差异化需求。

本功能把查询项管理从“按数量选布局”改为“用户配置位置 + 页面容量约束”：每个有权限的查询项稳定归属页面区或筛选抽屉，页面区始终按最小支持宽度保持整行对齐。

## 2. 产品原则

- 查询项只有位置差异，没有隐藏状态；页面未显示的字段必须在筛选抽屉中可用。
- 页面区优先保证一行对齐，不为了多放一个字段产生参差的第二行。
- 用户配置跨视口保持稳定；响应式只改变控件宽度，不擅自改变字段归属。
- 查询值跟随字段移动。保存布局不发起查询、不重置分页、不清空勾选。
- “重置查询”只清空条件，不恢复查询项布局；布局只由“恢复默认”改变。
- 使用稳定字段 ID 持久化，不保存翻译文本；语言切换不影响配置。

## 3. 出口订单规则

### 3.1 默认布局

- 页面显示：单号检索、业务类型、客户名称。
- 抽屉显示：责任操作、航线与单证、时效节点、状态/风险/结算相关条件。
- 单号检索是定位订单的必需查询项，固定在页面首位，不允许移入抽屉。

### 3.2 对齐容量

- 页面区以 24 轨（6 单位 × 4 轨）作为最小发布档位；容器加宽时轨道数按 24 / 32 / 40 步进，只改变控件宽度，不改变字段归属。
- 字段宽度使用语义角色换算：紧凑/标准 1 单位，宽/复合/区间/批量 2 单位。
- 查询动作区固定占 2 单位，字段区容量 10 单位；页面行数上限为 2 行，由 `pageSpec.layoutContract`（`minimumUnits/actionUnits/capacityUnits/maxRows`）显式声明，不能由字段数量自动推导。
- 用户拖入页面后若超过容量或行数上限，显示就地错误（已用/可用单位与行数）并禁用保存；不自动截断、不静默移回。

### 3.3 设置交互

- 查询动作区提供“查询项设置”齿轮按钮，使用 Arco Drawer 承载设置。
- 设置抽屉包含“页面显示”和“抽屉显示”两个列表。
- 支持鼠标在列表内排序、跨列表拖动；同时提供“移至页面/移至抽屉”按钮和 `Alt + ↑/↓`、`Alt + ←/→` 键盘排序。
- 抽屉提供取消、恢复默认、保存设置。取消不影响已应用布局；保存成功后立即更新页面与筛选抽屉。
- 筛选抽屉仍按业务分组展示，组内顺序服从用户配置；空分组不渲染。

## 4. 状态与持久化

- 本阶段使用版本化本地工作区存储：`ohl.shipment.export-order.query-fields.v1`。
- 载荷只保存 `version`、`pageFields`、`drawerFields`。
- 读取时去重、剔除未知字段、补回必需字段；新增字段默认进入抽屉。
- 存储失败时设置抽屉保持打开并保留草稿，显示明确错误。
- 高级筛选角标、分组计数、清空本组和草稿脏状态均按当前抽屉字段动态计算。

## 5. 功能边界

- 不改变查询接口、字段权限或订单筛选语义。
- 不提供查询模板命名、跨用户共享或服务端同步。
- 不允许把查询项真正隐藏，避免用户无法找到已有条件。

## 6. 验收标准

1. 默认布局在 1024、1366、1440+ 宽度及 200% 缩放下保持页面查询区一行对齐。
2. 中英文切换后字段不跳位，设置中的字段名称完整可读。
3. 字段可在两处之间移动并在各自区域排序；刷新页面后布局恢复。
4. 超容量时保存不可用，并说明已用/可用栅格。
5. 移动已有值的字段后值不丢失，保存布局不触发列表刷新。
6. 重置查询不会重置布局；恢复默认不会清空查询值。
7. 抽屉只展示当前归属字段，角标、组计数和清空本组结果正确。
8. 鼠标、键盘和非拖拽按钮均可完成配置，焦点与可访问名称明确。
